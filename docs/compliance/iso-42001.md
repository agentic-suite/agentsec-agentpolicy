# ISO/IEC 42001 Mapping

**ISO/IEC 42001** is the international standard for an **AI Management System (AIMS)** — the framework enterprise
buyers ask for when they govern AI. agentpolicy provides **controls** an AIMS can point at; this appendix maps
them. It is an **alignment mapping**, not a claim of certification (certification is the org's, not the tool's).

> Source: [ISO/IEC 42001 explained](https://www.iso.org/insights/iso-42001-explained)

## Annex A control families → agentpolicy

| Annex A area | What the AIMS must do | agentpolicy control |
|---|---|---|
| **A.2 — Policies related to AI** | Define AI policies | Policy-as-code: Cedar policies, git-reviewed, versioned (R7) |
| **A.3 — Internal organization** | Assign AI roles/responsibilities | Two-party policy review; PAP = the git repo |
| **A.5 — AI system impact assessment** | Assess impacts | The taxonomy + data-class dimension make impacts explicit |
| **A.6 — AI system life cycle** | Manage the lifecycle | Rule packs are versioned + incident-anchored; deprecation is explicit |
| **A.7 — Data for AI systems** | Govern data | The `data_class` dimension + redaction (LLM02) |
| **A.8 — Information for interested parties** | Transparency | The explain-decision contract + the audit log |
| **A.9 — Use of AI systems** | Control use | The five outcomes + budgets bound use |
| **A.10 — Third-party & customer relationships** | Govern third parties | The MCP-allowlist pack + tool-trust |

## What agentpolicy contributes vs. what it does not

- **Contributes:** an auditable, deterministic **control** (policy decisions + audit trail) that an AIMS can
  cite under A.2/A.6/A.9/A.10.
- **Does not contribute:** the management system itself (organizational processes, roles, impact assessments).
  Those are the deploying org's responsibility.
